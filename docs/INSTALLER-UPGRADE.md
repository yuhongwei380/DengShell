# Windows 安装升级流程

本流程自 v26.10.0-rc.3（构建 20261023148）安装包起提供。

1. 安装器先将完整载荷解压到自己的临时目录，安装助手再将受管理文件准备到安装目录所在卷。
2. 使用 Windows Restart Manager 检测程序占用，并核对可执行文件完整路径与进程创建时间；仅处理目标目录的 DevShell.exe 或旧名 DengShell.exe。
3. 检测到运行实例时，用户选择“关闭 DevShell 并继续安装”或“取消安装”。
4. 新版通过安装专用窗口消息正常退出；没有待处理任务时不再重复确认。有未保存编辑时可以返回保存或明确丢弃，有传输时可以等待完成或中止。保存和终端交接期间会等待完成。所有独立窗口退出前，主进程保留后端。
5. 旧版不识别安装消息时使用普通窗口关闭请求，由旧版自身显示退出确认。不能静默关闭的旧版需要在应用中确认。
6. 等待 15 秒仍未退出时，提供继续等待、强制关闭并继续或取消安装。强制关闭需要第二次明确确认，只操作之前核对过创建时间的目标进程。
7. 文件替换前再次检查占用；替换失败会恢复已经替换的程序文件。若恢复也失败，保留旧文件备份目录并明确显示路径。
8. 成功后由安装器写入卸载入口和快捷方式，完成页默认勾选启动 DevShell。原有个人配置、密钥、字体、背景均不参与文件替换。

安装期间通过按目录生成的 Windows 命名互斥量阻止新版实例重新启动。其他目录的 DevShell 不受影响。旧版尚无此启动保护，安装器会在写入前再检查。

若安装器在等待或替换过程中关闭，助手停止操作；已经替换的受管理文件会回滚。

`/S` 静默安装遇到运行实例时以非零状态退出，不弹窗，也不自动结束应用。交互式取消返回 1602。

辅助程序仅嵌入安装器临时目录，不安装到用户的 DevShell 目录。系统服务或其他应用不会被自动关闭；如果它们确实阻挡文件替换，安装失败并回滚。

验证命令：

```powershell
node scripts/tests/test-installer-exit.mjs
go test ./internal/installguard
$env:DEVSHELL_NATIVE_INSTALLER_TEST = '1'
go test ./internal/installguard -run TestInstallerTaskDialogNative -v
```

原生测试只驱动本次测试进程自己的提示框。进程检测和退出测试使用临时目录中的隔离测试程序，不操作用户正在运行的 DevShell。
